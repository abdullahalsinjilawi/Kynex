# Kynex

منصة ويب كاملة (عربي/إنجليزي) لمشاركة كود التدريب، معماريات النماذج، والداتا سيتس بين
مطوري الذكاء الاصطناعي. النماذج المدرّبة نفسها تُرفع لحساب HuggingFace تبع كل مستخدم
مباشرة (الموقع ما بيخزنها).

## البنية

```
├── backend/       Node.js + Express + MongoDB
├── frontend/      React + Vite + Tailwind CSS (عربي/إنجليزي، RTL/LTR تلقائي)
└── render.yaml    إعداد نشر جاهز لـ Render (Blueprint)
```

## التشغيل محلياً (خطوتين بتيرمنالين منفصلين)

### 1) الباك اند
```bash
cd backend
npm install
cp .env.example .env
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"  # انسخ الناتج لـ ENCRYPTION_KEY
npm run dev
```

### 2) الفرونت اند
```bash
cd frontend
npm install
cp .env.example .env
npm run dev
```
افتح: `http://localhost:5173`

## أول استخدام

1. سجّل حساب جديد — بيصير موصول مباشرة، ما فيه كود تفعيل ولا إيميل
2. ارفع مشروع، حط نجمة، جرّب كل شي

## عمل أول حساب أدمن

سجّل حساب عادي، بعدين افتح MongoDB وغيّر حقل `role` من `"user"` إلى `"admin"` يدوياً
بمجموعة `users`. بعدها هتلاقي "لوحة التحكم" بقائمة حسابك بالموقع.

# دليل النشر الكامل خطوة بخطوة (للإطلاق الفعلي)

هاد دليل تنفيذي حرفي — اتبعه بالترتيب. كل خطوة فيها بالضبط وين تروح وشو تضغط.
الكود جاهز 100%؛ الخطوات هون كلها إعدادات حسابات خارجية لازم تسويها إنت بنفسك
(محتاجة بياناتك وبطاقتك لبعض الخدمات، حتى لو الخطط مجانية).

## الخطوة 0: جهّز 3 حسابات خارجية مجانية

Render ما بيوفر قاعدة بيانات دائمة ولا تخزين ملفات دائم ولا إيميل — لازم توصلهم لحالك.
كل هدول عندهم خطة مجانية كافية للبداية:

### أ) قاعدة البيانات — MongoDB Atlas
1. روح [mongodb.com/atlas](https://www.mongodb.com/atlas) → أنشئ حساب مجاني
2. أنشئ Cluster جديد، اختر **M0 Free**
3. من **Database Access**: أنشئ مستخدم قاعدة بيانات (username + password) — احفظهم
4. من **Network Access**: أضف `0.0.0.0/0` (يسمح لـ Render يوصل — Render IPs متغيرة)
5. من **Connect → Drivers**: انسخ الـ Connection String (شكله
   `mongodb+srv://user:pass@cluster.mongodb.net/kynex`) — هاد رح يصير `MONGO_URI`

### ب) تخزين الملفات — Cloudflare R2
1. روح [dash.cloudflare.com](https://dash.cloudflare.com) → **R2 Object Storage**
2. أنشئ Bucket جديد، سمّيه مثلاً `kynex-projects`
3. من **Manage R2 API Tokens**: أنشئ API Token بصلاحية Read+Write
4. احفظ: **Account ID** (يبني منه الـ Endpoint:
   `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`)، **Access Key ID**، **Secret Access Key**

### ج) فحص الملفات — ClamAV (اختياري بس موصى فيه بقوة قبل فتح الرفع للعموم)
أسهل طريقة: VPS رخيص (DigitalOcean/Hetzner ~5$/شهر) شغّل عليه:
```bash
docker run -d -p 3310:3310 --restart unless-stopped clamav/clamav
```
بعدها `CLAMAV_HOST` = IP السيرفر، `CLAMAV_PORT` = 3310. لو تركتها فاضية، الموقع
بيشتغل عادي بس بدون فحص ملفات فعلي (وضع غير آمن لموقع مفتوح للعموم).

## الخطوة 1: ارفع الكود على GitHub

```bash
git init
git add .
git commit -m "Initial commit"
```
أنشئ repo جديد على GitHub وارفعه (خاص أو عام، حسب رغبتك).

## الخطوة 2: انشر على Render عبر Blueprint

1. روح [dashboard.render.com](https://dashboard.render.com) → **New → Blueprint**
2. اربط حساب GitHub تبعك واختر الـ repo
3. Render رح يقرأ `render.yaml` تلقائياً وينشئ سيرفسين: `kynex-backend` (Node) و
   `kynex-frontend` (Static Site) — اضغط **Apply**
4. أول نشر رح يفشل أو يطلع فاضي — طبيعي، لسه ناقصة متغيرات البيئة (الخطوة الجاية)

## الخطوة 3: عبّي متغيرات البيئة

من لوحة Render → سيرفس **kynex-backend** → **Environment** → أضف:

| المتغير | القيمة |
|---|---|
| `MONGO_URI` | من MongoDB Atlas (خطوة 0-أ) |
| `JWT_SECRET` | نص عشوائي طويل (32+ حرف) |
| `ENCRYPTION_KEY` | ناتج أمر `crypto.randomBytes(32).toString('hex')` بالأعلى |
| `S3_ENDPOINT` | من R2 (خطوة 0-ب) |
| `S3_ACCESS_KEY_ID` | من R2 |
| `S3_SECRET_ACCESS_KEY` | من R2 |
| `S3_BUCKET_NAME` | اسم الـ Bucket يلي أنشأته |
| `CLAMAV_HOST` / `CLAMAV_PORT` | لو جهّزت ClamAV (خطوة 0-ج)، وإلا اتركهم فاضيين |
| `FRONTEND_URL` | رابط سيرفس الفرونت اند (رح تشوفه بلوحة Render، مثلاً `https://kynex-frontend.onrender.com`) |

ثم سيرفس **kynex-frontend** → **Environment** → أضف:

| المتغير | القيمة |
|---|---|
| `VITE_API_URL` | رابط الباك اند + `/api` (مثلاً `https://kynex-backend.onrender.com/api`) |

بعد ما تعبّي الكل، اعمل **Manual Deploy** للسيرفسين حتى ياخدوا المتغيرات الجديدة.

## الخطوة 4: دومين مخصص (اختياري بس موصى فيه للإطلاق الفعلي)

1. من سيرفس **kynex-frontend** → **Settings → Custom Domains** → أضف الدومين تبعك
   (مثلاً `kynex.com`) واتبع تعليمات DNS يلي بتطلع (عادة CNAME عند مزوّد الدومين تبعك)
2. بعد ما يتفعل الدومين، حدّث `FRONTEND_URL` بسيرفس الباك اند لنفس الدومين الجديد
3. **مهم**: افتح `frontend/index.html` وابدل كل مكان فيه `https://kynex.example`
   بدومينك الحقيقي (الـ meta tags وJSON-LD)، وأعد النشر

## الخطوة 5: جدولة سكربتات التنظيف الدورية

المشروع فيه سكربتين لازم يشتغلوا بجدول ثابت (`backend/scripts/`):
- `cleanupBackups.js` — يمسح نسخ الملفات الاحتياطية الأقدم من 7 أيام
- `cleanupDeletedAccounts.js` — يحذف نهائياً الحسابات يلي عدّت 30 يوم على طلب حذفها

أسهل طريقة: **Render → New → Cron Job** لكل سكربت (يومياً مثلاً)، بنفس متغيرات
البيئة تبعت الباك اند. أو أي خدمة cron خارجية بتنادي endpoint تعمله لهالغرض.

## الخطوة 6: فحص نهائي قبل ما تعلن الإطلاق

- [ ] سجّل حساب حقيقي وتأكد وصل إيميل التفعيل فعلياً (مو بس بالـ logs)
- [ ] ارفع مشروع فيه مجلد فرعي (src/utils/...) وتأكد التنزيل رجع بنفس البنية
- [ ] جرّب تبديل اللغة (عربي/إنجليزي) وتأكد الاتجاه بينقلب صح
- [ ] اعمل حساب أدمن وتأكد لوحة التحكم شغالة
- [ ] لو فعّلت ClamAV: ارفع ملف [EICAR test file](https://www.eicar.org/download-anti-malware-testfile/)
      (ملف اختباري آمن مصمم يتعرف عليه أي فاحص فيروسات) وتأكد الرفع يترفض
- [ ] راجع نص الشروط بـ `/terms` مع محامي قبل الإعلان الرسمي

## ميزات الأمان المطبّقة

- جلسة عبر كوكي `httpOnly` (مو localStorage) — حماية من سرقة التوكن عبر XSS
- قفل حساب تلقائي بعد 5 محاولات دخول فاشلة
- حماية من NoSQL injection + input validation فعلي بأهم المسارات
- CORS مقيّد لدومين الفرونت اند فقط، مو مفتوح للكل
- توكن HuggingFace مشفّر بالكامل (AES-256-GCM)، كلمات السر مشفّرة (bcrypt)
- فحص ملفات حقيقي عبر ClamAV (لو مفعّل، أنظر الخطوة 0-د)
- سجل تدقيق لكل إجراء أدمن (Audit Log)
- تنظيف مسارات الملفات (path sanitization) ضد أي محاولة path traversal عند رفع مجلدات
- صفر ثغرات معروفة بمكتبات الإنتاج (`npm audit` نظيف على الباك اند)
- استثناء موثّق واحد: ثغرة متوسطة بـ esbuild (أداة بناء Vite) تؤثر فقط على سيرفر
  التطوير المحلي (`npm run dev`)، مش على الموقع المنشور فعلياً

## المزايا الكاملة

- **ثنائي اللغة بالكامل** (عربي/إنجليزي) — الواجهة كلها، واتجاه الصفحة (RTL/LTR)،
  ورسائل السيرفر والإشعارات كمان (مو بس الواجهة)
- تسجيل/دخول، تفعيل بكود، حذف حساب مؤجل 30 يوم مع إمكانية التراجع
- رفع مشاريع بملفات متعددة (ملفات مفردة أو مجلد كامل ببنيته الفرعية محفوظة)، تعديل
  المشروع بعد نشره (نصوص أو استبدال كامل للملفات مع نسخة احتياطية 7 أيام)، تراخيص
  جاهزة أو مخصصة مع شرح كل ترخيص
- بحث وفلترة متقدمة (اسم، فئة، لغة، وسوم)، صفحة مشروع بنظام Tabs (شجرة ملفات حقيقية
  + عرض README كـ Markdown منظّف بـ DOMPurify)، نجوم، تنزيل ZIP بنفس بنية المجلدات
  الأصلية، تعليقات، إشعارات (تعليق/نجمة/توثيق)، بلاغات
- API key شخصي لتنزيل المشاريع برمجياً (مرة كل 24 ساعة لكل مشروع)
- لوحة تحكم أدمن كاملة: مستخدمين، مشاريع، بلاغات، سجل تدقيق — حظر مستخدم بيخفي
  مشاريعه تلقائياً من العرض العام (بدون ما تحتاج تخفي كل مشروع يدوياً)
- Dark/Light mode تلقائي، هوية بصرية كاملة (شعار، أيقونات، صورة مشاركة اجتماعية)

## آخر نقطة قبل الإطلاق الرسمي (مش كود، قرار بشري)

**مراجعة محامي** لنص الشروط بـ `/terms` — المحتوى كامل واحترافي، بس أي منصة بتستقبل
محتوى من مستخدمين بمنطقة قانونية معينة (خصوصاً لو فيه مستخدمين من أوروبا/GDPR) لازم
تراجعها محامي فعلي قبل الإطلاق الرسمي، مش شي AI أو مطوّر يقدر يأكده.
